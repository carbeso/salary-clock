# 薪資時鐘 (Salary Clock) 需求規格說明書

本文件將原始 `salary_clock.pyw` 桌面小工具之概念與程式邏輯進行反向工程整理，並定義新一代「跨平台薪資時鐘」的完整功能需求與未來擴充藍圖。

---

## 1. 專案背景與概念緣起

### 1.1 核心概念
「薪資時鐘」旨在將抽象的月薪或時薪，轉化為**即時跳動的秒級累積金額**與**可視化進度條**。透過動態跳動的數字，為工作者帶來即時的正向心理激勵（「摸魚一秒、進帳一分」或「感受時間轉化為價值的過程」）。

### 1.2 原始版本 (`salary_clock.pyw`) 特性與局限分析

#### 原始版優點
1. **即時有感**：以 1 秒為單位自動刷新，金額動態跳動。
2. **極簡懸浮介面**：
   - 去除視窗邊框 (`overrideredirect`)
   - 視窗永遠置頂 (`topmost`)
   - 背景黑色穿透透明 (`-transparentcolor`)，宛如桌面原生抬頭顯示器 (HUD)。
3. **直覺操作**：
   - 滑鼠左鍵隨處按住可任意拖曳移動。
   - 按 `Esc` 或滑鼠右鍵即可快速關閉。
   - 關閉時自動記錄座標至 `window_pos.json`，下次啟動恢復位置。

#### 原始版局限與痛點
1. **薪資數值硬編碼**：程式碼內直接寫死 `MONTHLY_SALARY = 40000`，使用者無法透過介面調整薪資、切換幣別或設定獎金。
2. **計薪模型過於單純**：
   - 原始演算法採用「當月總秒數平均制」（無論休假、半夜睡覺都在算錢）。
   - 對於一般「固定上下班工時（例如 09:00~18:00）」或「按件計酬/自由工作者」，無法真實反映「上班工時內賺了多少」。
3. **平台與系統相依**：
   - 綁定 Python 3 與 Tkinter，且透明色機制依賴 Windows 專屬 API，無法在 macOS、Linux、iOS、Android 或一般網頁瀏覽器上運行。
4. **缺乏隱私防窺機制**：若同事或主管走近，直接以醒目大字體顯示目前賺了多少錢，缺乏一鍵遮蔽或模糊化功能。

## 2. 系統功能需求 (Functional Requirements)

新版系統將以**模組化**與**跨平台**為核心，拆分為核心計薪引擎、使用者介面、設定與儲存三大構面。

### 2.1 核心計薪引擎 (Calculation Engine)

系統應支援至少三種計薪模式，使用者可自由切換：

#### 模式 A：全月連續制（延續原版體驗）
- **適用情境**：被動收入、無休假概念的底薪感受、純心理激勵。
- **計算邏輯**：
  - 取當月實際總天數（自動處理平閏年 28/29/30/31 天）。
  - `當月總秒數 = 當月天數 × 24 × 3600`。
  - `每秒薪資 = 月薪 ÷ 當月總秒數`。
  - `累積金額 = 當月已經過秒數 × 每秒薪資`。
  - `本月進度 = (當月已經過秒數 ÷ 當月總秒數) × 100%`。

#### 模式 B：工作日與工時制（真實上班族模式）
- **適用情境**：標準週休二日或排班制工作者，只在「上班時間」內即時跳表計薪。
- **設定參數**：
  - 月薪金額（或標準時薪）。
  - 上班天數（預設每週一至週五，或指定每月工作天數）。
  - 每日工時起訖（例如 09:00 ~ 18:00）。
  - 休息時間扣除（例如 12:00 ~ 13:00 午休 1 小時不計薪）。
- **計算邏輯**：
  - 計算當月實際有效上班時數（扣除假日與午休）。
  - `有效每秒薪資 = 月薪 ÷ 當月有效上班總秒數`。
  - **即時狀態判斷**：
    - 非上班時間（下班、週末、午休）：計時器暫停累計，並顯示「休息中」或「下班狀態」。
    - 上班時間內：金額每秒平滑跳動。
  - 同時提供「今日已賺」與「本月已賺」雙維度統計。

#### 模式 C：碼錶/自由工時制（自由接案模式）
- **適用情境**：Freelancer、接案計時、專案專注計費。
- **設定參數**：目標時薪。
- **計算邏輯**：
  - 提供「開始計時 / 暫停 / 重設」操作。
  - 按下開始後，依據累計秒數以 `時薪 ÷ 3600` 即時累加金額。

### 2.2 介面與互動體驗需求 (UI/UX)

1. **多種檢視模式**：
   - **HUD 懸浮精簡模式**：僅顯示金額與微型進度條，去除多餘邊框，適合作為桌面小工具。
   - **完整儀表板模式 (Dashboard)**：包含本月日曆熱點、每日收益趨勢圖、當日倒數下班時間。
   - **隱私防窺模式 (Privacy / Boss Key)**：
     - 提供快捷鍵或滑鼠點擊切換。
     - 觸發時將金額轉為星號遮罩（如 `$ ****`）或切換為偽裝介面（如一般數字時鐘、待辦事項清單）。
2. **多幣別與數字格式化**：
   - 支援幣別符號設定（預設 `NT$` / `$`，亦可設定 `USD`、`JPY`、`EUR` 等）。
   - 支援千分位符號格式化（例如 `$40,000.00`）。
   - 支援微量金額顯示精確度切換（小數點後 2 位至 5 位）。
3. **里程碑與趣味激勵機制 (Milestone Rewards)**：
   - 「拿鐵指標」：當今日累積金額達到指定門檻（如 $150），跳出小提示「恭喜！今天已賺到一杯星巴克！☕」。
   - 「下班倒數」：顯示距離今日打卡下班還有幾小時幾分鐘。

---

### 2.3 設定與資料持久化 (Persistence)

1. **設定項**：
   - 計薪模式選擇（A/B/C）。
   - 薪資基礎（月薪或時薪）。
   - 工作時間設定（上班/下班/休息時段/工作日）。
   - 介面外觀設定（字體大小、主題色、透明度、置頂狀態）。
2. **儲存機制**：
   - 採用無伺服器相依的本機儲存機制（如 Web 的 `localStorage` / `IndexedDB`，或本機端的 JSON 設定檔）。
   - 支援設定匯出與匯入（JSON 格式），方便跨裝置移轉。

---

## 3. 非功能性需求 (Non-Functional Requirements)

1. **低資源耗用 (Lightweight)**：
   - 作為常駐桌面或背景執行的工具，CPU 佔用率應趨近於 0%，記憶體佔用應盡可能壓低。
2. **精確度與時間校正**：
   - 避免使用 `setInterval(1000)` 單純遞加累計秒數（會造成計時器漂移）。
   - 每次刷新計算必須以系統真實時間戳記（`Date.now()`）進行差值運算，保證絕對精準。
3. **跨平台相容性**：
   - 程式邏輯（核心計算法則）必須與 UI 渲染層徹底解耦。
   - 優先以現代 Web 標準（HTML5 / ES6+ / CSS3）實作核心，確保可在任何現代瀏覽器運行，並可無縫包裝至各平台。
